# 자료 형식 (protocol v1)

## 1. 파일

| 파일 | 위치 | 공개 여부 |
|---|---|---|
| `documents.jsonl` | `data/dev/` | 공개. 개발·디버깅용 |
| `queries.jsonl` | `data/dev/` | 공개. 관련 문서 ID 포함 |
| 평가용 질의·정답 | 저장소 밖 비공개 폴더 (W9, 검증 단계에서만 환경 변수로 위치를 받음) | 비공개. 작업자에게 주지 않음. **형식은 위와 같다** |

JSON Lines: 한 줄에 JSON 객체 하나, UTF-8(BOM 없음), 줄 끝 LF, 빈 줄 없음, 마지막 줄도 LF로 끝난다. 객체의 키는 아래에 적힌 것만 허용하며 추가 키는 오류다. 문자열은 유니코드 NFC로 저장한다.

## 2. documents.jsonl

```json
{"doc_id": "d001", "text": "커피 원두 보관 방법 안내. 원두 봉지는 밀봉해서 서늘하고 어두운 곳에 둔다."}
```

| 키 | 형 | 규칙 |
|---|---|---|
| `doc_id` | 문자열 | 정규식 `^d[0-9]{3}$`. 파일 안에서 유일. 줄 순서는 `doc_id` 오름차순 |
| `text` | 문자열 | 비어 있지 않음(공백만도 안 됨). 줄바꿈 문자 없음. 300자 이하 |

문서에는 제목 필드가 없다. 검색은 `text`만 본다. 개발용 문서 30개의 ID는 `d001`~`d030`이다.

## 3. queries.jsonl

```json
{"query_id": "q01", "text": "커피 원두 보관 방법", "relevant_doc_ids": ["d001"]}
```

| 키 | 형 | 규칙 |
|---|---|---|
| `query_id` | 문자열 | 정규식 `^q[0-9]{2}$`. 파일 안에서 유일. 줄 순서는 `query_id` 오름차순 |
| `text` | 문자열 | 비어 있지 않음. 줄바꿈 문자 없음. 100자 이하 |
| `relevant_doc_ids` | 문자열 배열 | 1개 이상, 중복 없음, 오름차순, 모두 같은 자료 집합의 `documents.jsonl`에 존재 |

`relevant_doc_ids`는 사람이 정한 관련 문서다. 검색 모듈은 이 값을 읽지 않는다(읽으면 규격 위반). 실행기는 요약 지표 계산에만 쓴다(raw-results.md §4). 개발용 질의 10개의 ID는 `q01`~`q10`, 평가용 질의는 `q11` 이후를 쓴다.

## 4. 문서 ID 비교

ID의 대소 비교는 Python 문자열 비교(코드 포인트 순)다. `d001` < `d002` < … < `d030`이며, 자릿수를 고정했으므로 숫자 순서와 같다. 동점 처리(search-interface.md §5)와 정렬은 모두 이 비교를 쓴다.

## 5. 읽기 규칙 (실행기·검증기 공통)

- 파일을 통째로 읽어 줄마다 `json.loads`. 잘못된 줄이 하나라도 있으면 전체를 오류로 처리하고 시작하지 않는다.
- 위 규칙 위반(중복 ID, 없는 관련 문서, 추가 키 등)도 시작 전 오류다. 일부만 골라 쓰지 않는다.
- 문서가 0개이거나 질의가 0개인 파일도 시작 전 오류다(지표의 분모가 0이 되는 입력을 받지 않는다).
- 문서·질의의 순서는 파일 순서를 유지한다. 실행기는 정렬하지 않는다.

## 6. 개발 자료의 출처

`data/dev/`의 문서와 질의는 이 프로젝트에서 직접 작성했다(외부 문서 인용 없음). 자세한 것은 `data/dev/README.md`.
