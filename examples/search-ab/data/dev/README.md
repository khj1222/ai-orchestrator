# 개발용 자료 (data/dev)

작성: 2026-09-20, W8 (Claude Code 세션이 직접 작성). 형식은 [protocol/data-format.md](../../protocol/data-format.md)를 따른다.

## 내용

- `documents.jsonl`: 짧은 한국어 문서 30개(`d001`~`d030`). 여섯 주제(커피, 발효 식품, 자전거, 실내 식물, 수면, 등산)에 5개씩. 각 문서는 한두 문장의 생활 정보다.
- `queries.jsonl`: 개발용 질의 10개(`q01`~`q10`)와 사람이 정한 관련 문서 ID. 질의는 문서를 그대로 옮기지 않고, 짧은 검색어나 질문 형태로 썼다. 관련 문서가 둘 이상인 질의(q05~q08)와 하나뿐인 질의를 섞었다.

## 출처와 사용권

- 모든 문장은 이 프로젝트를 위해 새로 썼다. 외부 문서·웹 페이지를 인용하거나 옮기지 않았다.
- 내용은 일반적인 생활 상식 수준이며 **사실의 정확성을 보증하지 않는다.** 검색 실험의 입력 자료일 뿐 정보 제공이 목적이 아니다.
- 이 폴더의 자료는 저장소 안에서 자유롭게 사용·수정·재배포할 수 있다(별도의 사용권 제한 없음).

## 작성 방식과 한계

- 규격의 토큰화는 공백 분리이며 형태소 분석을 하지 않는다. 그래서 `"원두는"`과 `"원두"`는 다른 토큰이다. 문서는 자연스러운 띄어쓰기로 썼고 매칭을 위해 조사를 억지로 떼지 않았다. 따라서 의미상 관련 있는 문서라도 토큰이 겹치지 않아 낮은 점수를 받을 수 있다(예: q06 "겨울 등산 준비물"과 d028). 이것은 자료의 결함이 아니라 기준 방법의 한계이며 보고서에 그대로 적는다.
- 개발용 질의의 관련 문서는 작성자가 의미로 판단했다. 09 §3에 따라 사람이 다시 확인한다.
- 평가용 질의(`q11` 이후)와 정답은 여기에 없다. W9에서 저장소 루트 `verifier/`에 비공개로 둔다.
